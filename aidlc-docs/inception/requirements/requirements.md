# 要件定義書

## インテント分析

| 項目 | 内容 |
|------|------|
| ユーザーリクエスト | 自分の自己紹介ページの作成 |
| リクエスト種別 | 新規プロジェクト（Greenfield） |
| スコープ見積もり | 単一コンポーネント（フロントエンドのみ） |
| 複雑度見積もり | Moderate（レスポンシブ対応＋カラーテーマ切り替え＋多言語対応） |

---

## 機能要件

### FR-01: コンテンツ構成
- **FR-01-1**: 基本プロフィールセクション（名前、写真、肩書き、一言メッセージ）を表示する
- **FR-01-2**: スキル・経歴・実績セクションを表示する
- **FR-01-3**: ポートフォリオ・作品集セクションを表示する
- **FR-01-4**: ブログ・記事リンクセクションを表示する
- **FR-01-5**: プロフィール写真領域はメイン画像領域（大）とサブ画像領域（小、3枚）で構成する
- **FR-01-6**: サブ画像をクリック／タップするとメイン画像が選択した画像に切り替わる
- **FR-01-7**: 現在メインに表示中のサブ画像は視覚的に強調される（選択状態）
- **FR-01-8**: ギャラリー機能（メイン＋サブ）はPC・タブレット表示のヒーロー領域でのみ提供する。スマホ名刺レイアウトでは従来どおり写真1枚を表示する

### FR-02: レスポンシブデザイン
- **FR-02-1**: PCブラウザ（幅 1024px 以上）では通常のWebページレイアウトで表示する
- **FR-02-2**: スマートフォン（幅 768px 未満）では名刺スタイルのレイアウトで表示する
- **FR-02-3**: 名刺レイアウトには「名前・肩書き・写真・スキルタグ・連絡先」を含める（リッチ名刺）

### FR-03: カラーテーマ切り替え
- **FR-03-1**: 3〜5個のカラーコードを設定できる
- **FR-03-2**: ページ上部に丸いボタン（カラーパレット）を配置し、クリックで選択する
- **FR-03-3**: 選択したカラーコードに応じてページ全体のデザインカラーが変わる
- **FR-03-4**: カラーテーマはページリロード時にデフォルトに戻る（localStorage保存なし）
- **FR-03-5**: デフォルトカラーはユーザーが具体的なカラーコードを指定する
- **FR-03-6**: 提供する4色のカラーテーマ
    | キー | カラーコード | 名称 | 役割 |
    |------|------------|------|------|
    | `mono` | `#000000` | Black | デフォルト（モノトーン基調） |
    | `lime` | `#7CFC00` | Shiun San | ビビッド・テック系 |
    | `rose` | `#B33E5C` | Rose Pink | エレガント・暖色系 |
    | `sky` | `#89C3EB` | Sky Blue | 爽やか・寒色系 |
- **FR-03-7**: 背景・文字・アクセントへの色割り当ては各テーマで WCAG AA（コントラスト比 4.5:1 以上）を満たすこと

### FR-04: SNS・連絡先リンク
- **FR-04-1**: GitHub プロフィールへのリンクを掲載する
- **FR-04-2**: LinkedIn プロフィールへのリンクを掲載する
- **FR-04-3**: その他技術系SNS（Zenn、Qiita等）のリンクを任意で掲載できる

### FR-05: 多言語対応
- **FR-05-1**: 日本語と英語の2言語に対応する
- **FR-05-2**: ページ上に言語切り替えボタンを配置する
- **FR-05-3**: 切り替えはクライアントサイドで即時反映する（ページリロードなし）

### FR-06: アニメーション・インタラクション
- **FR-06-1**: スクロールに連動したフェードインアニメーションを実装する
- **FR-06-2**: ボタン・リンクにホバーエフェクトを実装する
- **FR-06-3**: カラーテーマ切り替え時にスムーズなトランジションを実装する

## 非機能要件

### NFR-01: パフォーマンス
- **NFR-01-1**: Lighthouse パフォーマンススコア 90 以上を目標とする
- **NFR-01-2**: 初回表示（LCP）は 2.5 秒以内とする
- **NFR-01-3**: Next.js SSG（静的サイト生成）を使用し、ビルド時にHTMLを生成する

### NFR-02: アクセシビリティ
- **NFR-02-1**: WCAG 2.1 AA 基準に準拠する
- **NFR-02-2**: カラーテーマ切り替え時もコントラスト比 4.5:1 以上を維持する
- **NFR-02-3**: キーボードナビゲーションに対応する
- **NFR-02-4**: スクリーンリーダー対応（適切な alt テキスト・aria ラベル）

### NFR-03: 保守性
- **NFR-03-1**: プロフィール情報（名前、肩書き、一言メッセージ、写真パス、スキル、経歴、実績、ポートフォリオ、ブログ・記事リンク、SNS URL等）は単一のJSONファイル（`profile.json`）で一元管理する
- **NFR-03-1-1**: ビルド時に `profile.json` の内容が静的サイトに自動取り込みされる（Next.jsのSSGでビルド時読み込み）
- **NFR-03-1-2**: `profile.json` のスキーマは TypeScript の型定義と JSON Schema（または zod）でバリデーションする
- **NFR-03-1-3**: コード本体を変更せずに `profile.json` を編集するだけでコンテンツを更新できる
- **NFR-03-2**: カラーコードは設定ファイル（TypeScript定数）で定義し、コードを変更せずに追加・変更できる
- **NFR-03-3**: 多言語テキストは翻訳ファイル（JSON、`ja.json` / `en.json`）で管理する
- **NFR-03-4**: プロフィール情報の多言語フィールド（肩書き・一言メッセージ・経歴の説明等）は `profile.json` 内に `{ ja: "...", en: "..." }` 形式で保持する

### NFR-04: ホスティング・デプロイ
- **NFR-04-1**: AWS S3 静的Webサイトホスティングにデプロイする
- **NFR-04-2**: Next.js の `next export`（または `output: 'export'`）で静的ファイルを生成する
- **NFR-04-3**: AWS CDK（TypeScript）でインフラを Infrastructure as Code（IaC）として定義し、デプロイする
- **NFR-04-4**: CDK スタックは workspace 直下の `infra/` ディレクトリに配置し、フロントエンドコード（`web/` 等）と分離する
- **NFR-04-5**: CDK の Asset Deployment（`aws-s3-deployment.BucketDeployment`）で `out/` ディレクトリの静的ファイルを S3 バケットへ自動アップロードする
- **NFR-04-6**: S3 バケットには CloudFront ディストリビューションを前段に配置（OAC：Origin Access Control 利用）し、HTTPS 配信とキャッシュを実現する
- **NFR-04-7**: CDK デプロイは1コマンド（`npm run deploy` 等）で完結し、ビルド → 静的ファイル生成 → S3 アップロード → CloudFront キャッシュ無効化 まで一括実行する
- **NFR-04-8**: 環境（開発／本番）はCDK のスタック単位で分離可能とし、最低限「prod」スタックを定義する
- **NFR-04-9**: デプロイ手順・前提条件（AWSアカウント、CDK Bootstrap、必要IAM権限）は ROOT の `README.md` に整理する

### NFR-05: テスト
- **NFR-05-1**: 純粋関数（カラーテーマ変換、言語切り替えロジック等）にプロパティベーステストを適用する
- **NFR-05-2**: コンポーネントの基本的なレンダリングテストを実装する

## 技術スタック決定

| カテゴリ | 技術 | 理由 |
|---------|------|------|
| フレームワーク | Next.js 14（App Router） | SSG対応、S3デプロイ可能、TypeScript標準 |
| 言語 | TypeScript | 型安全性、保守性 |
| スタイリング | Tailwind CSS | レスポンシブ対応が容易、カラーテーマ切り替えと相性良 |
| アニメーション | Framer Motion | スクロールアニメーション・トランジション |
| 多言語 | next-intl または react-i18next | クライアントサイド言語切り替え |
| テスト | Vitest ＋ fast-check（PBT） | 純粋関数のプロパティベーステスト |
| デプロイ | AWS S3 + CloudFront（CDK で IaC） | 静的ホスティング、HTTPS配信、キャッシュ |
| IaC | AWS CDK v2（TypeScript） | プログラマティックにインフラ定義、型安全 |

|---------|------|------------|

---

## 制約・前提条件

- バックエンドAPIは不要（静的サイト）
- 認証・ログイン機能は不要
- データベースは不要
- プロフィール情報はコード内の設定ファイルで管理（CMSなし）
- カラーコードの具体的な値はユーザーが後で指定する

---

## 成功基準

- PCとスマホで適切にレイアウトが切り替わること
- スマホ表示が名刺らしいデザインになっていること
- 3〜5個のカラーテーマが正しく切り替わること
- 日本語・英語が正しく切り替わること
- AWS S3 にデプロイ可能な静的ファイルが生成されること
- AWS CDK（TypeScript）で S3 ＋ CloudFront 構成をデプロイできること
